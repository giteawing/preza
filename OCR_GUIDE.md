# Подсказка агентам: OCR и восстановление редактируемого текста

## Цель

Создать копию исходной презентации, в которой визуальная вёрстка не меняется, а текст,
«запечённый» в растровые изображения, закрывается фоном и воспроизводится поверх него
редактируемыми текстовыми блоками PowerPoint.

## Исходник и результат

- Исходник в репозитории: `СВК_10_принципов_управления_дизайн.pptx`.
- Запрошенное пользователем имя (`СВК_10_принципов_управления_20_марта_2026_финал-1.pptx`)
  в текущем checkout отсутствует; перед началом работы нужно проверить, не является ли файл
  в репозитории той же презентацией под другим именем.
- Пользователь передал исходник тремя обычными файлами: `p1.pptx`, `p2.pptx`, `p3.pptx`.
- В презентации 62 слайда: `p1` = глобальные 1–19, `p2` = 20–39, `p3` = 40–62.
- Планируемый результат: отдельный `.pptx`; исходные части не перезаписывать.

## Как распознавать и восстанавливать текст

1. Получить настоящий LFS-объект: файл в обычном checkout может быть только 134-байтным
   указателем Git LFS. Ожидаемые параметры бинарника: 195 678 257 байт, SHA-256
   `652cd345e15310fdbec7ad246c4c78e05fe561ce53e2e942955707f25143087b`.
   Проверять размер, ZIP-сигнатуру и SHA-256. В текущей среде `git pull` выполняется, но
   Git LFS не установлен; прямое обращение к LFS Batch API получило корректную ссылку,
   однако соединение с `github-cloud.githubusercontent.com` закрывается во время TLS.
2. Распаковать PPTX как ZIP и составить карту `slide -> relationship -> media` по
   `ppt/slides/_rels/slideN.xml.rels`.
3. Отрендерить каждый слайд или извлечь его полноразмерный фон. Для OCR использовать русский
   и английский языки (`rus+eng`), сохраняя координаты слов/строк и confidence.
4. OCR делать минимум в двух вариантах: на оригинале и на увеличенной в 2–4 раза контрастной
   копии. Для светлого текста на тёмном фоне дополнительно применять инверсию. Сверять
   результаты вручную по изображению слайда.
5. Группировать слова в логические текстовые блоки, не только в строки OCR. Особое внимание:
   `ё/е`, `й/и`, кавычки, тире, переносы, номера принципов, латиница в аббревиатурах.
6. Определять оформление по пикселям исходника и геометрии блока:
   - координаты и размеры переводить пропорционально из пикселей в EMU слайда;
   - цвет брать пипеткой из внутренней области глифов/фона;
   - шрифт сначала искать во встроенных/тематических шрифтах PPTX, затем подбирать ближайший;
   - размер, жирность, регистр, межстрочный интервал и выравнивание подгонять сравнительным
     рендером.
7. Чтобы не менять вёрстку, оставить исходную картинку на месте. Под каждым новым текстовым
   блоком поставить фигуру без контура, залитую локальным цветом фона (либо аккуратный патч
   исходного изображения), а поверх — прозрачный текстовый блок. Не закрывать декоративные
   элементы.
8. Валидация: открыть результат библиотекой PPTX, убедиться, что все добавленные надписи —
   обычные `a:t`/text runs, затем отрендерить результат и сделать pixel-diff с исходником.
   Проверить отсутствие переполнения, обрезания и сдвигов на каждом слайде.
9. После каждого законченного набора слайдов обновлять таблицу ниже, коммитить и пушить.

## Правило обновления журнала

Для каждого слайда записывать **полный проверенный текст**, включая заголовки, подписи,
нумерацию и служебные надписи. Если часть не читается, помечать её как `[НЕРАЗБОРЧИВО: …]`,
а не угадывать. После проверки заменять пометку точной формулировкой.

## Реализация итоговых файлов

Скрипт `scripts/build_editable_text_layer.py` воспроизводимо создаёт три итоговые части.
Каждая строка OCR помещена в отдельную обычную фигуру PowerPoint (`a:t`) с именем
`EDITABLE OCR — slide … — block …`. Чтобы исходная растровая вёрстка не получила ни одного
визуального сдвига, OCR-фигуры имеют прозрачный цвет текста. Найти, выделить и редактировать
их можно через **Главная → Упорядочить → Область выделения**. Исходные изображения и уже
существующие редактируемые фигуры не удалялись и не перемещались. Это безопасный первый
редактируемый слой; для полной визуальной замены конкретного блока следует убрать
прозрачность его текста и локально закрыть исходные пиксели фоновым патчем.
